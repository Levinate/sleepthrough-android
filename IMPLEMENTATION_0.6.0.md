# Android 0.6.0 — кабинет вместо воронки

## Что изменено

- Экран запуска — авторизация Supabase или **Try test account**. Гостевой локальный профиль больше не открывает кабинет.
- Вход не зависит от покупки. Удалены активные маршруты квиза, профиля квиза, email-воронки, тарифов, checkout и платёжного онбординга. Даже прямой переход на старый адрес ведёт к входу или Today. Модули старой воронки не входят в APK-бандл.
- Кабинет повторяет navy/lavender дизайн веба. Янтарный цвет используется для ночной помощи. Пять стабильных пунктов нижней навигации: Today, My reset, Insights, Diary, Account.
- Today: пробуждения, I'm awake, компактная скрываемая строка посещений, следующий урок и график. Очки и число уроков перенесены в Account.
- Путь из 28 интерактивных уроков: закреплённые недели и узлы с понятным следующим шагом. Практики и сохранение результата не менялись.
- Samsung Health, Health Connect, общий отчёт и дневник сохранены. Личные данные здоровья подключаются в личном аккаунте; тестовый аккаунт использует только пример данных.
- Для старого WebView вместо зависшего запуска показываются ссылки на обновление WebView/Chrome. Данные не очищаются.

## Доступ и данные

`src/access.mjs` проверяет доступ для каждого маршрута. Право входа — сохранённый пользователь Supabase либо явно открытый тестовый режим. Существующие признаки `started` или `profile.demo` из старого гостевого хранилища не дают доступ.

Тестовый режим хранит данные в `state:demo`. Личный аккаунт — в `state:<user_id>`. Экран выхода не открывает старый гостевой профиль и не читает его повреждённые данные. Старое `state:local` сохраняется на устройстве; автоматического переноса в аккаунт нет. Данные тестового режима не отправляются в Supabase и не переносятся в личный аккаунт.

Сессия и записи используют существующий SecureVault. Ключи сервиса Supabase и ключ подписи не входят в исходники. Клиент использует публичный ключ. Проверены RLS обеих таблиц: SELECT/INSERT/UPDATE/DELETE ограничены `auth.uid() = user_id`; анонимный HTTP-запрос не получает записи. Изменений схемы базы нет.

Регистрация и восстановление используют существующий PKCE/deep-link `sleepthrough://auth/callback`. Email-подтверждение включено в Supabase. Доставку писем на личный адрес в этой версии отдельно не проверяли.

## Проверка

- 37 тестов логики, доступа, хранилища, объединения отчётов и совместимости загрузчика; плюс проверка сервера раздачи APK (38 вместе).
- APK собран, `:app:lintDebug` прошёл.
- На Android 16 прошли тесты реального WebView/Keystore: мост хранилища, чтение прежнего v1, пересоздание Activity и полный сценарий кабинета. После последних правок полный сценарий повторён успешно.
- Сценарий APK проверяет блокировку гостевого входа и старых адресов, тестовый аккаунт, пять пунктов меню, перенос очков в Account, ночной протокол и заметку, чек-ин, интерактивный урок, повторное открытие, сохранность данных и отсутствие горизонтального переполнения.
- На Android 9 прошли отдельные проверки хранилища. Полный сценарий на штатном WebView 69 не запускается: нужен WebView/Chrome 100+. Для этого случая есть проверенный загрузчик с инструкциями обновления. Это ограничение указано при скачивании.
- Реальный импорт сна с Samsung-устройства остаётся проверкой на телефоне пользователя: эмулятор не подтверждает качество данных часов.
