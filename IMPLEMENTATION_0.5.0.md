# SleepThrough 0.5.0 pilot — реализация правок команды

Дата: 6 ноября 2026. Android package: `com.sleepthrough.app`; versionCode: `5`.

Источник требований: «SleepThrough MVP – правки для Даурена.md» и 8 HTML-референсов из архива. Референсы использованы как материалы для дизайна, их сторонние скрипты не запускались. Палитра SleepThrough сохранена: navy, lavender, фиолетовая покупка и янтарная ночная помощь.

## Что реализовано

| Область | Результат |
|---|---|
| Квиз | 21 иллюстрированный экран, тёмная тема, ответ одним нажатием, защита повторного нажатия, назад/пропуск, экран CDC, вопрос о трекере |
| Профиль | До трёх поддержанных ответами факторов, полосы, объяснение конкретными ответами, стартовая частота ночей и изменяемая цель |

| Ночь | Янтарная I'm awake, успокоение, действие по фактору, заметка на утро, дыхание 4/6 с паузой, шаг возврата к отдыху |
| Утро | Три вопроса кнопками; нулевые пробуждения пропускают вопрос длительности; показ отложенных мыслей и сравнение записанных недель |

## Осознанные уточнения к документу

1. Проценты — доля сигналов квиза среди показанных факторов с потолком 89%, **не вероятность диагноза**. Факторы без оснований не выдумываются ради трёх полос. Цель на 28-ю ночь можно изменить; приложение не обещает её достижение.
2. Стартовая частота трудных ночей в неделю не смешивается с единицей «пробуждения за одну ночь» на графике.
3. Повторное открытие активного эпизода продолжает его. Отдельная кнопка явно создаёт новое пробуждение. Записи кнопки обозначаются нижней границей до утренней оценки.
4. Протокол не запускает обратный отсчёт 20 минут и не требует следить за часами. Веб содержит ориентир «около 20 минут» без таймера; пользователь выбирает следующий шаг по самочувствию.
5. Автоматическое ограничение окна сна до 6–7 часов и его коррекция не реализованы: это отдельный клинически значимый сценарий, требующий более полного допуска, правил и проверки. В приложении есть обычное расписание практики/чек-ина.
6. Health Connect уже реализован, поэтому он не назван «скоро». Apple Health и прочие прямые интеграции отсутствуют.
7. Онбординг сокращён с 8 экранов до 5; веб дополнен экскурcией по реальным элементам кабинета.
8. Подписка и отмена сейчас **демонстрационные**, без настоящего списания. Реальный Stripe test-mode требует подключения аккаунта владельцем. Демо-отмена не выдаётся за отмену Stripe-подписки. Гарантия помечена как проект платной политики.
9. События воронки остаются внутри локального состояния; внешней рекламной аналитики нет. Содержимое заметок, ответы и email в события не включаются.
10. Главный баннер веба сохранён по последнему пожеланию пользователя. Обновлены только воронка, кабинет, служебные страницы и футер.

## Стек

Android: Capacitor 8, JavaScript ES modules, HTML/CSS, esbuild; Kotlin, AndroidX Health Connect, Android Keystore, AlarmManager/NotificationCompat; Supabase JS для существующих аккаунтов и приватной синхронизации. Нативная Android-оболочка включает ресурсы интерфейса внутрь APK, поэтому локальный режим работает без сервера.

Веб: существующие HTML/CSS/JavaScript и Node.js HTTP server; общий модуль воронки собирается esbuild. Изменений схемы БД или публикации на GitHub/Railway в этой задаче не выполнялось.

## Установка

Установить `SleepThrough-0.5.0-pilot.apk` поверх версии 0.4.0 тем же Android-профилем. **Не удалять старое приложение и не очищать его данные** перед обновлением. Сохранены package ID и прежний debug signing key. Это sideload pilot APK для тестирования, не Play Store release.

Минимум Android 9; нужен обновлённый Android System WebView/Chrome, поддерживаемый Capacitor. Health Connect должен быть доступен на устройстве, а Samsung Health должен передавать ему данные сна с отдельным согласием пользователя.

## Проверка и границы

- 33 Node-теста: модель факторов, ночные эпизоды, быстрый чек-ин, даты планов, недели, отчёты Samsung + дневник, пропуски стадий, конфликты синхронизации, восстановление хранилища, допуск взрослого аккаунта.
- Android 16: полный сценарий настоящего APK, повторное открытие, 28-урочный интерфейс, реальное шифрованное хранилище и совместимость старого формата. Основной набор 12 instrumented-тестов прошёл; финальный сценарий повторён после визуальных изменений.
- Android 9: 5 нативных проверок хранилища прошли, включая чтение после пересоздания экрана и миграцию v1 → v2. Полный интерфейс на этом эмуляторе не тестировался: системный WebView 69 слишком стар для Capacitor.
- Веб: проверены ширина 390 px, 21 ответ, согласие, демо-оплата, все шаги онбординга, экскурсия, ночная заметка, чек-ин, перезагрузка и собственные отчёты. Старые проверки уроков/авторизации/HTTP сохранены.
- Реальные данные Samsung/часов и доставку email на личный адрес пользователя на эмуляторе проверить невозможно. SMTP зависит от настройки существующего Supabase-проекта.
- Новый формат не может восстановить уже потерянный или повреждённый старый Android Keystore key. В таком случае исходная запись сохраняется и ошибка показывается; автоматического удаления нет.

## Сборка

Из корня репозитория: `node build-web-mvp.mjs` — веб-воронка.

Из `mobile`: `node --test test/*.test.mjs`, `node build.mjs`, `node_modules/.bin/cap sync android`.

Из `mobile/android`: Gradle `:app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug` с JDK 21 и Android SDK 36.

Снимки результата, планов, ночной практики и чек-ина находятся рядом с APK в `screenshots/`. Все показанные там данные синтетические.
